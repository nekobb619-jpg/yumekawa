# お宝図鑑（コレクション）— レア度・拡張方針

対象コード：`index.html` 内 `window.TREASURE_LIST` / `window.rollTreasureDrop` /
`window.showTreasureReveal` / `window.openTreasureBookModal`（実装の全体像は
`architecture-content.js.md` の「8. お宝図鑑」を参照。ここではデータ設計・
今後の拡張ルールだけをまとめる）。

## 1. レア度階層（2026-07-24 改定）

| レア度 | 呼び方       | 現在の種類数 | 排出重み | テーマカラー |
|--------|--------------|--------------|----------|--------------|
| ★1     | ふつう       | 13種         | 65%      | グレー（無地）|
| ★2     | レア         | 9種          | 25%      | 青系 `#60a5fa` |
| ★3     | 超レア       | 4種          | 8%       | アンバー系 `#f59e0b` |
| ★4     | 伝説級       | 2種          | 2%       | 紫系 `#a855f7`（r3より強い発光アニメーション）|

- 全体のドロップ率は変更なし：ステージクリアごとに **15%** の確率で1個抽選
  （`Math.random() >= 0.15 return null` の外枠は据え置き）。
- レア度の重みは `window.rollTreasureDrop()` 内の
  `r < 0.65 ? 1 : (r < 0.90 ? 2 : (r < 0.98 ? 3 : 4))` で決定。
- ★4は「存在するだけで特別」なレベルを想定（現状2種のみ、複数持っていても
  automatically コンプ扱いにはしない＝図鑑コンプ演出は将来の拡張候補）。

## 3. テーマ・命名の一貫性ルール（今後アイテムを足すときも踏襲する）

- 世界観のキャラクター（ニコ＝ユニコーン的マスコット、クロぽん）や
  「意図を見ぬく力」（このアプリのaim-recognition問題形式）、宝島クラフト、
  漢検10級のテーマから外れないこと。
- 見た目・意味ともに小学校低学年〜中学年の子どもにポジティブで安心できる
  ものにする（怖い・生々しい表現は禁止。persona-yumekawa.mdの表現ルールに準拠）。
- `desc`は1〜2文、子どもが読める語彙で。絵文字iconは他アイテムと視覚的に
  被らないものを選ぶ（今回`t27`の💎は既存アイテムと非重複を確認ずみ）。
- idは`t` + 連番（歯抜けなし）。既存の番号は変更しない（セーブデータの
  `treasureBook`キーとして永続化されるため、idのリネームは既存プレイヤーの
  コレクションを破壊する＝**絶対に既存idをリネーム/再利用しない**）。

## 4. 今後の拡張チェックリスト

新しいお宝バッチを追加するときは、以下を順番に実施する：

1. `window.TREASURE_LIST`に新規オブジェクトを追記（既存idの直後、レア度ごとに
   まとまりを保つ）。
2. 排出重みを変える場合のみ`rollTreasureDrop()`の閾値式を更新
   （個数が増えるだけなら閾値は変更不要。同一レア度内の抽選は
   `pool[Math.floor(Math.random() * pool.length)]`で均等ランダムなので、
   種類が増えるほど1種あたりの体感排出率は下がる想定でOK）。
3. 新レア度階層を新設する場合のみ`showTreasureReveal()`と
   `openTreasureBookModal()`のクラス分岐・CSSを追加（★5を作る場合は
   `.treasure-reveal-box.r5`等のパターンを踏襲）。
4. Node での構造検証（id重複なし・レア度カウント）＋ 統計シミュレーション
   （数百万回試行で実測排出率が設計値に近いか）＋ Playwrightでの描画確認
   （新レア度の演出モーダル・図鑑グリッド）を必ず実施してから納品する。
5. このファイルの表・リストと、`architecture-content.js.md`の「8. お宝図鑑」
   セクションの種類数を両方更新する。

## 5. ちしきカード（2026-10-02追加）

りおがお宝28種（★1〜★4）をすべてコンプリートしたため、学習そのものを集める要素として追加。
- 単元（ステージ）ごとに1枚。🥉その単元をクリア → 🥈3日以上あけてミス2つ以下でクリア →
  🥇さらに7日以上あけてノーミスでクリア（`window.KCARD_RULES`）。間をあけて思い出す＝分散学習。
- 完璧主義に配慮し、🥉はミスがあってもOK、🥈はミス2つまで許容し、ノーミスは🥇だけ。
- Qは付与しない（稼ぎの抜け道にしない）。保存は `saveData.knowledgeCards[stageId] = [段階, 達成日(日本時間の日数)]`
  で本体行（進捗扱い、切り詰め対象外）。
- お宝図鑑モーダルの下に教科ごとに表示。タップでその単元の `job_desc` を1つランダム表示（見返し学習）。
- 表示対象は `matchesGradeFilter` を通るステージだけなので、ステージを追加すると自動でカードも増える。


## きょうのまなびプラン ＋ まなびのなかま（2026-10-02 ホーム改革）

- ホーム最上段に `js/tutor-plan.js` の「きょうのまなびプラン」。毎日1回だけ3ステップを組んで `saveData.tutorPlan` に固定する
  （①ふくしゅう：苦手3問以上なら苦手撃破ラボ、なければ3日以上あいたクリア済みステージの古い順 ②あたらしく学ぶ：今週の answerLogs が
  少ない教科の未クリアステージ（🆕優先）③よむ・ちょうせん：おはなし→なぞとき→探偵ラボのうち、まだのもの）。
- 達成判定は状態から計算（ステージ＝reviewDatesが今日、おはなし＝bookLastReadDate、なぞとき＝`getTodayMysteryInfo()`）。
  苦手撃破ラボと探偵ラボだけは `tutorPlanMark("weak"|"detective")` で印をつける（index.html の exitToMainMenu / finishDynamicPractice）。
- 3つ全部で +5Q（1日1回、`PLAN_REWARD_Q`）・れんぞく日数・log_db に「🎯まなびプラン」。
- `js/mascots.js`：プラン達成回数（`tutorPlanDoneCount`）で なかま が増える（もちっこ0／ゆきんこ1／ぽてまる3／くろしお6／ゆめりん10）。
  えらんだ子（`selectedFriend`）がプランカードで クロぽん先生の隣に出る。各キャラに本当の豆ちしき（ユニコーンは語源）。
- キャラはすべてオリジナルSVG。すみっこぐらし・クロミ・ちいかわ等の既存キャラ（他社の著作物）は公開リポジトリなので使わない。
- ホームの並び：プラン → おはなし/なぞとき → 📚教科 → 🔁ふくしゅう・とっくん → 👑特別指令 → 🧰どうぐばこ → 🎁ごほうび → 👨‍👩‍👧おうちの人と。
  学ぶ場所を ごほうび より上に置く。新しいボタンは横長ボタンを増やさず、該当セクションの `.tile-grid` にタイルで足す。
- 問題を解く画面では、えらんだ なかま が 正解・まちがい・「わからない」に吹き出しでリアクションする（`js/mascots.js` が
  `showQuestionStep`/`triggerCorrectAnswer`/`triggerWrongAnswer`/`triggerSkipAnswer` を後ろから包む。進行は止めない）。
  読む時間ロック（READ_LOCK）は2026-10-02に0へ（次の問題への移り変わりのもたつきはUX的に良くない、というユーザー判断）。
  代わりに、40文字以上の問題を2.5秒未満で正解すると「はやい！問題も読めたかな？」と声をかける。
